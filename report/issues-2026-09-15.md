# Issue sweep of anthropics/claude-code — 2026-09-15

What the public tracker already says about the things this repo measures, and
where the two disagree. Method: `tools/issues.py` (24 GitHub searches, 2 pages
each, sorted by reactions; 2,356 unique issues; score = keyword hits +
log(reactions) + log(comments) + open bonus). The ranked lists are in
`issues-2026-09-15-sweep.md`; this file is the hand-read cross-reference.
Two claims were re-tested against the local 674-session corpus (§7).

Our own issues: [#94177](https://github.com/anthropics/claude-code/issues/94177)
(forensics from 30 sessions) and [#94417](https://github.com/anthropics/claude-code/issues/94417).

## Addendum 2026-09-15 — #90018 A/B (`totalTokensReminder` off)

16 fresh `claude -p` sessions on Opus 5, 8 tasks × 2 arms, ABBA: `config`
(everything as configured, reminder on, default `padded-countdown`) vs `nore`
(same + `CLAUDE_CODE_TOTAL_TOKENS_REMINDER=off`; the env var outranks
`settings.json` in the 2.1.272 binary). Runner: `experiments/ab-config-vs-bare/run.py
--arms config,nore`; per-run numbers in `data/results-nore-2026-09-15.jsonl`.

- The env var works in `-p`: 0 `<total_tokens>` blocks in all 8 `nore`
  transcripts, 4–18 in `config`.
- In the 6 pairs with the same call count, cache write differs by **+23 to
  +111 tokens** for config — the literal size of the blocks (4 blocks → +23,
  8 → +79/+111), ≈ 6–14 tokens per block, US$ 0.000–0.001 per session.
- **No mid-session rewrite in any of the 16 transcripts**: `cache_read` only
  grows; ~15 post-tool boundaries per arm, 0/15 in both.
- The two large `cache_creation` values (38.7k on the first call, `cache_read`
  0) are a cold shared prefix (tools+system, 17.7k) under 3 parallel workers,
  in both arms (t4 both, t5 config) — not the reminder.
- Accuracy 7/8 both (the eighth task needs the judge).

Verdict: consistent with the 61,850-boundary measurement (0.09%). The
reminder does not create a cache floor here; both reports in the issue went
through a non-Anthropic gateway. 16 sessions cannot distinguish 0.09% from
0.1%; what they show is that the block itself is nearly free.
